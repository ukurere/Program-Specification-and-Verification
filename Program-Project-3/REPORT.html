1. Мета роботи

Мета роботи — набути практичних навичок автоматизованого тестування вебінтерфейсів з використанням фреймворку Selenium WebDriver та мови програмування C#. Зокрема, навчитись керувати браузером програмно, взаємодіяти з елементами веб-форм (текстові поля, textarea, dropdown, checkbox, datalist, кнопки), перевіряти стан елементів після виконання дій, налаштовувати WebDriver з автоматичним підбором версії ChromeDriver за допомогою бібліотеки WebDriverManager.

2. Теоретичні відомості

2.1. Selenium WebDriver

Selenium WebDriver — відкритий фреймворк для автоматизованого керування браузером. На відміну від Selenium RC (застарілої архітектури), WebDriver взаємодіє з браузером напряму через специфічний протокол — WebDriver Protocol (W3C-стандарт), — без потреби у проміжному сервері. Це забезпечує більш надійну і швидку взаємодію.

Основні компоненти Selenium для C#:

  • Selenium.WebDriver — основна бібліотека; містить інтерфейс IWebDriver, клас ChromeDriver, методи пошуку елементів (FindElement), навігації (Navigate().GoToUrl()), таймаути.
  • Selenium.Support — допоміжні компоненти: SelectElement для роботи з <select>-елементами, WebDriverWait для явного очікування умов.
  • OpenQA.Selenium.By — клас-фабрика стратегій пошуку елементів: By.Id, By.Name, By.CssSelector, By.XPath тощо.

2.2. ChromeDriver та WebDriverManager

ChromeDriver — виконуваний файл, що реалізує WebDriver-протокол для браузера Google Chrome. Критично важливо, щоб версія ChromeDriver точно відповідала версії встановленого браузера Chrome — інакше виникає помилка ініціалізації.

Для автоматичного підбору та завантаження відповідної версії ChromeDriver використовується бібліотека WebDriverManager. Стратегія VersionResolveStrategy.MatchingBrowser визначає встановлену версію Chrome та завантажує ChromeDriver тієї ж версії, що усуває необхідність ручного оновлення виконуваного файлу.

new DriverManager().SetUpDriver(new ChromeConfig(), VersionResolveStrategy.MatchingBrowser);

2.3. Headless-режим Chrome

У headless-режимі браузер запускається без графічного інтерфейсу. Це дозволяє виконувати тести у середовищах без дисплея (CI/CD-сервери, контейнери Docker) та прискорює виконання. Аргументи, що передаються через ChromeOptions:

  • --headless — вмикає headless-режим;
  • --no-sandbox — вимикає пісочницю Chrome (необхідно у деяких Linux-середовищах);
  • --disable-dev-shm-usage — запобігає помилкам нестачі пам'яті у контейнерах.

2.4. Локатори елементів

Selenium підтримує кілька стратегій пошуку DOM-елементів:

ЛокаторОписПриклад
By.IdПошук за атрибутом idBy.Id("my-check-2")
By.NameПошук за атрибутом nameBy.Name("my-text")
By.CssSelectorCSS-селекторBy.CssSelector("button[type='submit']")

2.5. Явне очікування (WebDriverWait) та IJavaScriptExecutor

WebDriverWait реалізує явне (explicit) очікування: виконання тесту призупиняється до виконання заданої умови або до спливання тайм-ауту. Це більш надійно, ніж неявне очікування (ImplicitWait), оскільки чітко визначає умову завершення очікування.

IJavaScriptExecutor дозволяє виконувати довільний JavaScript-код у контексті браузера. Це необхідно, коли елемент перекривається іншими елементами або виходить за межі видимої зони (прокрутки), що спричиняє помилку ElementClickInterceptedException. Прокрутка до елемента та JavaScript-клік вирішують цю проблему у headless-режимі:

var js = (IJavaScriptExecutor)_driver;
js.ExecuteScript("arguments[0].scrollIntoView(true);", element);
js.ExecuteScript("arguments[0].click();", element);

2.6. Паттерн IDisposable у xUnit

У xUnit тестовий клас може реалізовувати інтерфейс IDisposable. Метод Dispose() автоматично викликається після кожного тест-методу. Це гарантує закриття браузера та звільнення ресурсів навіть у разі провалу тесту, що запобігає витоку процесів браузера.

3.2. Ініціалізація та завершення тестів

Клас WebFormTests реалізує інтерфейс IDisposable. Конструктор класу відіграє роль setup-методу: він налаштовує та запускає ChromeDriver перед кожним тестом. Метод Dispose() закриває браузер після кожного тесту.

Лістинг 2. Ініціалізація WebDriver (конструктор та Dispose)

public class WebFormTests : IDisposable
{
    private readonly IWebDriver _driver;
    private const string Url = "https://www.selenium.dev/selenium/web/web-form.html";

    public WebFormTests()
    {
        new DriverManager().SetUpDriver(
            new ChromeConfig(),
            VersionResolveStrategy.MatchingBrowser);   // автопідбір версії ChromeDriver

        var options = new ChromeOptions();
        options.AddArgument("--headless");             // без графічного інтерфейсу
        options.AddArgument("--no-sandbox");
        options.AddArgument("--disable-dev-shm-usage");

        _driver = new ChromeDriver(options);
        _driver.Manage().Timeouts().ImplicitWait = TimeSpan.FromSeconds(5);
        _driver.Navigate().GoToUrl(Url);
    }

    public void Dispose()
    {
        _driver.Quit();   // закриває браузер після кожного тест-методу
    }
}

Виклик VersionResolveStrategy.MatchingBrowser забезпечує завантаження ChromeDriver, що точно відповідає версії встановленого Google Chrome, що усуває помилки ініціалізації драйвера.

3.3. Тестові сценарії

Сценарій 1: Заповнення форми та перевірка підтвердження

Тест вводить текст у текстове поле та textarea, після чого натискає кнопку Submit. Через особливості headless-режиму кнопка Submit перекривається іншими елементами при звичайному кліку — для вирішення цього застосовано прокрутку до елемента та JavaScript-клік. Тест перевіряє, що після відправки форми URL змінився на сторінку підтвердження та з'явилось повідомлення «Received!».

Лістинг 3. Сценарій 1 — відправка форми

[Fact]
public void SubmitForm_WithTextAndTextarea_ShowsConfirmationPage()
{
    var textInput = _driver.FindElement(By.Name("my-text"));
    textInput.SendKeys("Hello Selenium");

    var textarea = _driver.FindElement(By.Name("my-textarea"));
    textarea.SendKeys("This is a test message");

    var submitButton = _driver.FindElement(By.CssSelector("button[type='submit']"));
    ((IJavaScriptExecutor)_driver).ExecuteScript(
        "arguments[0].scrollIntoView(true);", submitButton);
    ((IJavaScriptExecutor)_driver).ExecuteScript(
        "arguments[0].click();", submitButton);

    var wait = new WebDriverWait(_driver, TimeSpan.FromSeconds(5));
    wait.Until(d => d.Url.Contains("submitted-form"));

    Assert.Contains("submitted-form", _driver.Url);

    var message = _driver.FindElement(By.Id("message"));
    Assert.Equal("Received!", message.Text);
}

Перевірки:

  • URL після сабміту містить підрядок "submitted-form";
  • Елемент з id="message" містить текст "Received!".

Особливість: WebDriverWait чекає зміни URL до 5 секунд, що робить тест стійким до мережевих затримок.

Сценарій 2: Вибір з Dropdown та встановлення Checkbox

Тест вибирає значення «Two» зі списку (елемент <select>) через клас-обгортку SelectElement, після чого програмно встановлює чекбокс у позначений стан через JavaScript-клік (для обходу ElementClickInterceptedException у headless-режимі). Тест перевіряє текст і значення вибраного пункту, а також стан чекбоксу.

Лістинг 4. Сценарій 2 — dropdown та checkbox

[Fact]
public void SelectDropdown_AndCheckCheckbox_ValuesAreCorrect()
{
    var js = (IJavaScriptExecutor)_driver;

    var dropdown = new SelectElement(_driver.FindElement(By.Name("my-select")));
    dropdown.SelectByText("Two");

    var checkbox = _driver.FindElement(By.Id("my-check-2"));
    js.ExecuteScript("arguments[0].scrollIntoView(true);", checkbox);
    if (!checkbox.Selected)
        js.ExecuteScript("arguments[0].click();", checkbox);

    Assert.Equal("Two", dropdown.SelectedOption.Text);
    Assert.True(checkbox.Selected);
    Assert.Equal("2", dropdown.SelectedOption.GetAttribute("value"));
}

Перевірки:

  • Текст вибраного варіанту — "Two";
  • Атрибут value вибраного варіанту — "2";
  • Чекбокс my-check-2 знаходиться у відміченому стані.

Особливість: SelectElement (з пакета Selenium.Support) інкапсулює роботу з <select>-елементом; метод SelectByText() знаходить пункт за видимим текстом.

Сценарій 3: Введення пароля та вибір з Datalist

Тест вводить пароль у поле типу password та текст «New York» у поле datalist (поле з підказками). Перевіряється, що атрибут value кожного поля містить введені дані, а також тип поля пароля.

Лістинг 5. Сценарій 3 — поле пароля та datalist

[Fact]
public void FillPassword_AndDatalist_FieldsContainCorrectValues()
{
    var passwordInput = _driver.FindElement(By.Name("my-password"));
    passwordInput.SendKeys("SecurePass123");

    var datalistInput = _driver.FindElement(By.Name("my-datalist"));
    datalistInput.Clear();
    datalistInput.SendKeys("New York");

    Assert.Equal("SecurePass123", passwordInput.GetAttribute("value"));
    Assert.Equal("New York",      datalistInput.GetAttribute("value"));
    Assert.Equal("password",      passwordInput.GetAttribute("type"));
}

Перевірки:

  • Поле пароля містить введений рядок «SecurePass123»;
  • Поле datalist містить значення «New York»;
  • Тип поля пароля — "password" (атрибут type).

5. Висновок

У ході виконання програмного проєкту 3 реалізовано три автоматизованих UI-тести для веб-форми з використанням фреймворку Selenium WebDriver 4.44 та мови C#. Тести охоплюють ключові типи взаємодії з HTML-формами: введення тексту, вибір зі списків, робота з checkbox, datalist та полем пароля.

У процесі роботи вирішено наступні практичні задачі:

  • автоматичний підбір та встановлення ChromeDriver засобами бібліотеки WebDriverManager зі стратегією VersionResolveStrategy.MatchingBrowser;
  • налаштування headless-режиму Chrome для виконання тестів без графічного інтерфейсу;
  • вирішення проблеми ElementClickInterceptedException у headless-режимі шляхом прокрутки до елемента та виконання кліків через IJavaScriptExecutor;
  • реалізацію явного очікування зміни URL після відправки форми за допомогою WebDriverWait;
  • коректне звільнення ресурсів браузера після кожного тесту через паттерн IDisposable.

Результат: усі 3 тести успішно пройдено. Автоматизоване UI-тестування забезпечує можливість регресійної перевірки вебінтерфейсу при кожній зміні коду без ручного відтворення сценаріїв.
